======================================================================
              T2S2 SYSTEM MAINTENANCE & MONITORING FRAMEWORK
======================================================================

The T2S2 Maintenance and Monitoring Framework is an enterprise-grade 
user notification, session management, and real-time logging solution 
designed for IT administrators and deployment tools.

MANUAL USER NOTIFICATION VS. AUTOMATED DEFERRAL WORKFLOW:
Manually coordinating maintenance windows with active logged-in users 
often leads to data loss, lost productivity, or compliance delays. This 
framework provides an interactive interface directly to remote users, 
allowing them to acknowledge maintenance or postpone action for fixed 
intervals, all while streaming real-time event logs to a central monitor.

CORE FUNCTIONALITY:
* Interactive Multi-Stage GUI: Displays a clean, visual alert prompt to 
  logged-in users with options to proceed immediately or postpone for 
  5, 10, or 30 minutes.
* Visual Attention Flashing: Uses asynchronous UI timers to flash yellow 
  background alerts, ensuring high visibility without locking window responsiveness.
* Custom Comment Logging: Provides a dedicated text area for users to log 
  custom reasons or feedback when postponing maintenance or submitting custom actions.
* Accountability & Termination Traps: Traps early process terminations, 
  automatically logging the initiator's account name for audit trails.
* Automatic Log Directory Management: Automatically creates and maintains 
  a dedicated "Logs" folder to store all user interaction logs, fallback tracking files, and session activity.
* Real-Time Monitoring Sub-System: Features a dedicated GUI monitor 
  ("ControlCenter") with a high-contrast terminal theme (black/chartreuse) 
  that listens to central logs and issues audible and visual cues upon updates.
* Background Execution & State Management: Auto-hides background console 
  windows and disables previously used deferral options if a snooze time expires.

======================================================================
                        RUN & SETUP GUIDE
======================================================================

This framework consists of two primary scripts designed to run natively 
within the Windows PowerShell environment.

----------------------------------------------------------------------
STEP 1: ENVIRONMENT, FOLDER CREATION & SHARE REQUIREMENTS
----------------------------------------------------------------------
Ensure your infrastructure and source paths are configured as follows before deployment:

1. Create Source Script Directory (CRITICAL):
   Create a dedicated folder named "ShowPrompt" directly under C:\ on the 
   UTIL server so it is accessible via network share at:

   \\UTIL\C$\ShowPrompt\

   Place your "ShowPrompt.ps1" script inside this folder.

2. Central Log Share: The scripts are configured by default to target 
   the central network log path:
   
   \\UTIL\c$\Logs\

   The framework automatically checks for the "Logs" folder and creates it 
   if it does not already exist. Ensure the host executing the notification 
   script has write permissions to this location. If network access is interrupted, 
   fallback logs are automatically created in the local temp directory 
   (%TEMP%\MaintLog_Fallback.txt).

3. Windows PowerShell: Requires standard PowerShell 5.1 or higher with 
   System.Windows.Forms and System.Drawing assemblies supported.

----------------------------------------------------------------------
STEP 2: CREATING THE PDQ INVENTORY TOOL (CRITICAL)
----------------------------------------------------------------------
To trigger the maintenance prompt on target computers directly from PDQ Inventory, 
you must create a custom Tool definition if it has not already been configured:

1. Open PDQ Inventory.
2. Navigate to Tools > Customize... (or Right-click a computer > Tools > Create Tool).
3. Click New Tool and configure the following fields:

   - Name: End User Session Request Tool
   - Run Type: Remote
   - Run As: Logged on User
   - Timeout: 3600 Seconds
   - Command (CMD / Batch execution - NOT a native PowerShell tool step):
     copy "\\UTIL\C$\ShowPrompt\ShowPrompt.ps1" "C:\Windows\Temp\ShowPrompt.ps1" /Y && powershell.exe -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\Windows\Temp\ShowPrompt.ps1"

4. Click Save Tool to finalize the setup.

----------------------------------------------------------------------
STEP 3: LAUNCHING THE REAL-TIME LOG MONITOR (CONTROLCENTER)
----------------------------------------------------------------------
The monitor window should be opened by the administrator to track user 
responses and maintenance statuses live.

1. Locate the file "controlcenter.ps1" (or "Run_ControlCenter.bat").
2. Execute the batch wrapper "Run_ControlCenter.bat" or run:

   powershell.exe -ExecutionPolicy Bypass -NoProfile -File "controlcenter.ps1"

3. The monitor window ("T2S2 Monitor - Active") will open in a high-contrast 
   black interface. 
4. The background PowerShell console window automatically hides itself on launch.
5. The monitor polls the log directory every 1 second, automatically 
   flashing and beeping when new entries arrive from endpoint computers.

----------------------------------------------------------------------
STEP 4: EXECUTING THE USER NOTIFICATION PROMPT
----------------------------------------------------------------------
To issue a maintenance prompt to a target endpoint:

1. Right-click the target machine in PDQ Inventory, go to Tools, and select 
   "End User Session Request Tool" (or press Execute).
2. The user will be presented with Stage 1 (Initial Maintenance Alert).
   - Clicking "PROCEED" initiates the security handshake for log-off.
   - Clicking "DEFER" navigates to Stage 2 (Postponement Options).
3. In Stage 2, the user can choose 5, 10, or 30-minute deferrals or enter 
   a custom note before submitting.
4. Deferral countdowns write minute-by-minute status updates directly to 
   the central log file inside the created Logs folder, visible live on 
   the ControlCenter Monitor.
